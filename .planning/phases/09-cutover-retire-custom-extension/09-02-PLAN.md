(Railway) e publicar uma versão da Taqciti que já vem configurada para falar com esse backend. Ninguém do time vê
mudança ainda.

**3. Riscos de cada ação**
- Task 1: roteiro mandar clicar num botão que não existe — o botão "Relatório" da tela ao vivo fica OCULTO em sessão
  discovery (`shouldShowManualReportButton`, `frontend/src/lib/lens.ts`), e todo cliente criado pela Taqciti nasce
  `mode='discovery'` (`extension_session_service.py:26`), então a pessoa ficaria travada no meio da reunião; o único
  caminho é "Gerar PRD" na página do projeto, que só destrava com prontidão ≥ 65% — se a conversa não cobrir as áreas,
  o botão fica cinza e a pessoa não sabe por quê (o número também não se atualiza sozinho: só ao recarregar a página);
  sair da sala antes de o PRD ser salvo deixa `reports` vazio (pitfall 3); "resolver" a falta de prontidão gerando o
  relatório pela tela de sessão encerrada inverteria a ordem travada pelo D-03; SQL que escreve no banco; apagar por
  prefixo `vis%` (pegaria o cliente real `visus`).
- Task 2: deploy sair de branch errada (o deploy sai da `master`, HANDOFF §2) e a prova rodar sem o código da Fase 8;
  `GEMINI_API_KEY` ausente (pipeline mudo); valor de chave colado na conversa/arquivo; `DOCUDATA_URL` definida e o teste
  `ZZ-TESTE` exportar para o DocuData real (pitfall 4).
- Task 3: release sair sem a URL de produção (a Taqciti cai no padrão `http://localhost:8000`) ou com o streaming
  desligado; conferência que engana — (i) exigir "localhost:8000 ausente" do bundle nunca passa (reprova até a release certa), porque
  `AGENTE_BACKEND_URL_DEFAULT` (agenteConfig.ts) mantém o literal `||"http://localhost:8000"` minificado mesmo com a
  variável definida, e acaba sendo ignorado; (ii) olhar a tela do Agente num perfil do Chrome que já usou a Taqciti
  mostra a config SALVA em `chrome.storage.local`, não o padrão da build, e "passa" mesmo com release errada; (iii) olhar
  a pasta errada — `~/Desktop` não existe nesta máquina (o OneDrive redireciona a Área de Trabalho para

  e "não lista nada", passando no vácuo; o instalador copia por cima sem apagar os `assets/*.js` velhos (nomes com hash
  diferentes), que contaminariam a conferência; link de release de repo não oficial (phishing por link); alguém editar o
  `release.yml` do subtree deste repo achando que resolve; cortar a release a partir de um repo original que NÃO tem o
  código das Fases 7-8 (o `git subtree push` foi adiado no D-03 da Fase 7 "para quando o time decidir") — a build sairia
  sem streamer/associação e a prova SC1 falharia mesmo com as variáveis certas.
