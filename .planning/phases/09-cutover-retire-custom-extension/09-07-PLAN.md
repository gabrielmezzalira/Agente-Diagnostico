## Plano em 7 seções (obrigatório — CLAUDE.md §"Regras de Planejamento de Tasks")

**1. O que muda (em linguagem comum)**
Depois do test drive, devolvemos o "carro de teste": apagamos do banco de produção o cliente de mentira `ZZ-TESTE…`
criado na prova e duas sessões esquecidas da Fase 8. Apagar no banco de produção não tem volta, então a regra é:
primeiro listar exatamente o que vai sair, a pessoa confere e autoriza, apaga-se por identificador (nunca "tudo que
começa com..."), e depois confere-se que sumiu — e que o cliente real `visus` continua lá.

**2. Como vai ser alterado**
- Task 1 (auto): rodar SÓ os `select` de listagem do `09-UAT.md` e anotar os ids e o projeto de cada sessão.
- Task 2 (humano): o usuário confere a lista e roda os `delete` por id (sessões primeiro, depois o projeto), ou autoriza
  explicitamente o executor a rodá-los naquele momento.
- Task 3 (auto): `select` de confirmação (zero linhas para os ids; `visus` presente) e registro no teste 7; commit
  `docs(09-07)`.

**3. Riscos de cada ação**
- Task 1: listar por prefixo largo e incluir cliente real; as 2 sessões da Fase 8 pertencerem a um projeto que não é
  de teste.
- Task 2: apagar o cliente real `visus` (`like 'vis%'`); apagar o projeto antes das sessões; apagar dado que ainda
  servia de evidência.
- Task 3: registrar dado sensível no UAT.
- Fora do banco: se a prova exportou ao DocuData real (decisão do teste 1), o dado continua lá.

**4. Como prevenir**
- Task 1: listagem por id exato e por `client like 'ZZ-TESTE%'` (prefixo que nenhum cliente real usa); a listagem
  mostra a qual projeto cada sessão pertence.
- Task 2: só ids que aparecem na listagem; sessões primeiro (os filhos saem por `ON DELETE CASCADE`), depois o projeto
  com a dupla trava `id in (...) and client like 'ZZ-TESTE%'`; só depois de `gate_d02: aprovado` (evidência já
  registrada no UAT).
- Task 3: anotar só ids de teste e contagens.
- DocuData: se o teste 1 registrou exportação aceita, o checkpoint lembra o time de limpar lá (ação externa).

**5. Como consertar (plano de rollback)**
- Banco: `delete` não tem `git revert`. Se algo errado for apagado, restaurar pelo backup point-in-time do Supabase
  (painel → Database → Backups) — decisão e ação do time. Por isso o checkpoint exige conferência antes.
- `09-UAT.md`: `git revert` do commit `docs(09-07)`.

**6. Decisões que são do usuário/time**
- **DECISÃO EM ABERTO (Task 2):** autorizar cada `delete` (ação irreversível em produção, fora do repo — CLAUDE.md).
- Se as sessões `ce75b9af…`/`6cd362ad…` estiverem ligadas a um projeto que NÃO é `ZZ-TESTE`: apagar só as sessões ou
  também o projeto — o time decide olhando a listagem.
- Limpeza no DocuData (se houve exportação): do time.

**7. Verificação (ponta a ponta)**
- `select` de confirmação: 0 linhas para os ids apagados e para `client like 'ZZ-TESTE%'`; 1+ linha para `client = 'visus'`.
- Teste 7 do `09-UAT.md` com `result: pass`.
