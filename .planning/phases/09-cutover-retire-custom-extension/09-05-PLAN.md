## Plano em 7 seções (obrigatório — CLAUDE.md §"Regras de Planejamento de Tasks")

**1. O que muda (em linguagem comum)**
Depois que o time aprovou a Taqciti numa reunião real, jogamos fora a extensão antiga do repositório: o arquivo
compactado (zip) e a pasta com o código dela. É como tirar da prateleira um produto descontinuado — ele continua
guardado no "arquivo morto" (o histórico do git) e pode voltar com um comando. Quem ainda tem a extensão antiga
instalada no navegador não é bloqueado (D-14): o backend continua aceitando o que ela manda.

**2. Como vai ser alterado**
- Task 1: `git rm agente-diagnostico-extension-v1.0.0.zip` → commit `chore(09-05): remove o zip da extensão antiga`.
- Task 2: `git rm -r extension/` → commit `chore(09-05): remove a pasta da extensão antiga`; em seguida as suítes
  completas (backend e frontend). Os dois commits são remoção pura; nenhum arquivo é editado.

**3. Riscos de cada ação**
- Task 1: algum arquivo ainda referenciar o zip (só `labels.ts` referenciava, resolvido no 09-04).
- Task 2: algum consumidor esquecido da pasta (CI, build, Dockerfile, testes); sobrar lixo não rastreado na pasta
  (o `test ! -e extension` falharia); remover junto algo do contrato do backend por engano.
- Ambos: rodar antes da prova aprovada (viola D-02).

**4. Como prevenir**
- Pré-condição verificada em cada task: `gate_d02: aprovado` no `09-UAT.md`.
- Task 1: grep no `frontend/src` (fora de testes) pelo nome do zip = 0 antes do `git rm`.
- Task 2: o inventário do 09-RESEARCH ("O que pode quebrar") mostrou zero consumidores (sem `.github/` na raiz, sem
  `package.json` na raiz, Dockerfile só copia `backend/`, vitest só `src/`); a pasta não tem arquivos ignorados/não
  rastreados hoje (`git status --ignored extension/` vazio); o `<verify>` confere que o commit só lista caminhos
  `extension/`; suítes completas + `-k sc3` depois.

**5. Como consertar (plano de rollback)**
- Task 1: `git revert <sha-do-commit-do-zip>`.
- Task 2: `git revert <sha-do-commit-da-pasta>` — a pasta volta inteira, com os testes `node --test`.
- Nada em produção muda (o Railway só copia `backend/`; a Vercel só builda `frontend/`).

**6. Decisões que são do usuário/time**
- Já decidido: remover de vez via `git rm` (D-09), depois da prova (D-02).
- **Fora do repo, só registrado (decisão 8 do planejamento, não agir):** apagar ou manter a release v1.0.0 no GitHub
  e a pasta antiga do Drive — continua em "Decisões pendentes do time" no `09-UAT.md` e vai no SUMMARY.

**7. Verificação (ponta a ponta)**
