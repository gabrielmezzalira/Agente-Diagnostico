<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| User input → ProjectFormPage | pricing_api_key entered as password; must not be readable in DOM or sent to backend in GET responses |
| Frontend → Backend | pricing_api_key sent in POST/PUT body only; never in URL params |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-11-02-01 | Information Disclosure | pricing_api_key in form state | mitigate | input type="password" + autoComplete="new-password" prevents browser autofill exposure; key cleared from form state after submit |
| T-11-02-02 | Information Disclosure | ProjectResponse includes has_pricing_api_key boolean (not the key) | accept | Backend (plan 11-01) ensures key is never returned; frontend only sees the boolean, not the secret |
| T-11-02-03 | Spoofing | provider field is free-form select | accept | Backend validates against known providers in llm_factory; unknown value raises ValueError before any LLM call |
| T-11-SC | Tampering | No new npm packages in this plan | accept | No new package installs — no slopcheck required |
</threat_model>
