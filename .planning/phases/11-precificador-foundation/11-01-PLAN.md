<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Frontend → Backend API | Project create/update payload carries pricing_api_key in plaintext — must never be logged or returned |
| Backend → Supabase Vault | Secret stored via vault_create_secret RPC; secret_id stored in projects table, plaintext never written to DB |
| Backend → LLM Provider | api_key fetched from Vault at invocation time; only passed to provider SDK, never returned to frontend |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-11-01 | Information Disclosure | POST /projects — pricing_api_key in request body | mitigate | Exclude pricing_api_key from model_dump before DB insert; store only secret_id via Vault; key never logged |
| T-11-02 | Information Disclosure | ProjectResponse — pricing_api_key_secret_id column | mitigate | _VAULT_EXCLUDED set strips pricing_api_key_secret_id from all responses; frontend only receives has_pricing_api_key boolean |
| T-11-03 | Tampering | pricing_api_key_secret_id UUID stored in projects row | accept | UUID is opaque reference; Vault restricts access to service role key; frontend cannot call Vault RPC directly |
| T-11-04 | Elevation of Privilege | llm_factory.py — lazy imports load provider packages | accept | Packages are installed at deploy time; lazy import pattern does not introduce new attack surface vs top-level imports |
| T-11-SC | Tampering | npm/pip package installs (langchain stack) | mitigate | Packages are well-known langchain ecosystem (langchain.com); slopcheck before install if adding further packages |
</threat_model>
