<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Client → POST /pricings/:id/approve | Action is irreversible — approved pricings become read-only snapshots |
| Client → DELETE /pricings/:id | Delete must be blocked for approved pricings to preserve history integrity |
| Client → pricing_history | Snapshots are immutable; inserts only, no updates or deletes exposed |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-11-03-01 | Tampering | DELETE /pricings/:id on approved pricing | mitigate | 409 guard in delete_pricing: if status == "approved" raise HTTP 409; approved snapshots remain in pricing_history |
| T-11-03-02 | Tampering | POST /pricings/:id/approve called twice | mitigate | 409 guard in approve_pricing: if already approved raise HTTP 409 "Already approved" |
| T-11-03-03 | Tampering | pricing_history.snapshot can be manually updated in Supabase | accept | No API update endpoint for pricing_history; history is append-only from the API perspective; manual DB access requires service-role credentials |
| T-11-03-04 | Elevation of Privilege | project_id in POST body could reference another user's project | accept | Single-user deployment (per REQUIREMENTS.md v2 deferred: multi-user); no row-level security required in v2.0 |
| T-11-03-05 | Denial of Service | Large feature lists passed to PricingCalculator | accept | Calculation is O(n) summation with no external calls; no practical DoS surface for single-user tool |
| T-11-SC | Tampering | No new pip installs in this plan | accept | All LangChain packages added in 11-01; this plan only imports from app.core which is local |
</threat_model>
