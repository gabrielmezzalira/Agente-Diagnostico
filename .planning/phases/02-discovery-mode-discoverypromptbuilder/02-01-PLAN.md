## Plano de execução — 7 seções obrigatórias (CLAUDE.md)

**1. O que muda (em linguagem comum)**
Hoje o sistema só conhece um "sabor" de reunião: o de vendas, com 8 áreas fixas e o portfólio
comercial da CITi embutido nos prompts. Este plano ensina o sistema a reconhecer um segundo sabor —
"discovery" — que olha 18 áreas (metade sobre o produto/problema, metade sobre os dados) e conversa
como um facilitador que mapeia o gargalo e a solução, sem falar de portfólio de vendas. Como uma
cozinha que ganha um segundo cardápio: os mesmos utensílios (o motor de reunião), duas ementas. O
cardápio de vendas continua exatamente igual — ninguém encosta nele.

**2. Como vai ser alterado (arquivos, ordem, commits atômicos)**
Ordem: Task 1 → Task 2 → Task 3. Cada task com TDD (teste RED antes, código GREEN depois) em commits
separados. Task 1: `coverage_areas.py` (adiciona `DISCOVERY_AREA_SET`, aditivo) e `session_state.py`
(campo `mode` + ramo `mode` em `_init_coverage`), testes em `test_discovery_mode.py`. Task 2: novo
`discovery_prompt_builder.py`. Task 3: `pipeline.py` (seleção de builder + repasse do mode). Cada
