## Plano em 7 seções (obrigatório — CLAUDE.md §"Regras de Planejamento de Tasks")

**1. O que muda (em linguagem comum)**
Criamos a tela "Escolher cliente": uma lista com busca (que acha "Açaí" mesmo digitando "acai"), um botão
para criar um cliente só com o nome, e — se a lista não carregar — o campo antigo de colar o código da
sessão, como plano B. A tela não sabe de onde vêm os clientes: ela recebe a lista pronta, como um cardápio
impresso que pode vir de qualquer cozinha. Hoje a "cozinha" ainda não existe (as rotas do backend dependem
da decisão B1); por isso os testes usam uma cozinha de mentira (fake). Escolher é sempre em dois passos
(marcar a linha e depois clicar no botão do rodapé), para um clique errado não criar sessão no Agente.

**2. Como vai ser alterado**
Três commits:
- Task 1: novos `clientDirectory.ts` (tipos e portas, mecânico), `clientSearch.ts` (funções puras) com
  teste, e `taqciti/src/test/fakeClientDirectory.ts` (fakes de teste).
- Task 2: novos `ClientPicker.tsx` e `ClientPickerList.tsx` com teste — lista, busca, seleção, contador e os
  estados carregando/vazio/erro/selecionado.
- Task 3: novos `ClientCreateForm.tsx` e `ManualSessionIdForm.tsx`, encaixados no `ClientPicker.tsx`, e o
  teste estendido (criar cliente, duplicado, plano B).
Tudo é código novo; nenhum arquivo existente muda.

**3. Riscos de cada ação**
- Task 1 — busca com regex de acentos feita à mão errar casos ("ç", "ã"); ordenação quebrar com acento.
- Task 1 — a porta acoplar-se ao formato do backend (ex.: devolver `ProjectResponse` inteiro).
- Task 2 — o atalho do Meet capturar letras digitadas na busca.
- Task 2 — o clique numa linha já disparar o vínculo (sessão órfã no Agente).
- Task 2 — nome de cliente com HTML vir a ser interpretado (XSS).
- Task 2 — o arquivo do picker passar de 200 linhas.
- Task 3 — o campo de ID manual aparecer com a lista carregada (contraria D-02).
- Task 3 — o `Esc` do formulário de criar minimizar o painel em vez de voltar à lista.
- Task 3 — o texto digitado sumir após um erro de criação.

**4. Como prevenir**
- `s.normalize('NFD').replace(/\p{M}/gu, '').toLocaleLowerCase('pt-BR')` + `Intl.Collator('pt-BR')`
  (Don't Hand-Roll do RESEARCH); casos de teste com "açaí"/"acai", "São Paulo"/"sao paulo", caixa mista.
- `ClientSummary = { id; client; name }` — só o necessário (T2/LGPD); erros próprios
  (`DuplicateClientError`, `ClientDirectoryUnavailableError`).
- Só `SearchField`/`TextField` do kit (seguram o teclado); nenhum `<input>` cru.
- Clique na linha só alterna `selected`; o vínculo sai do botão do rodapé; teste conta zero chamadas de
  `onConfirm` ao clicar na linha.
- Texto sempre como filho JSX; grep negativo de `dangerouslySetInnerHTML`; teste com nome
  `<img src=x onerror=alert(1)>` renderizado literalmente.
- Lista separada em `ClientPickerList.tsx`; gate automático de 200 linhas.
- `ManualSessionIdForm` só é renderizado quando `status === 'error'`; teste com `status='ready'` prova a
  ausência do campo.
- `onKeyDown` no formulário: `Escape` → `stopPropagation` + volta à lista; teste com listener em `document`.
- Valor do campo mantido em estado local enquanto `error` muda; teste "erro preserva o texto".

**5. Como consertar (plano de rollback)**
- Cada task é um commit de arquivos novos: `git revert <sha>` remove só aquela parte. Nada importa esses
  arquivos até os planos 08-10/08-14, então reverter não quebra nenhuma tela existente.

**6. Decisões que são do usuário/time**
- **DECISÃO EM ABERTO B1 (não bloqueia este plano):** formato real da lista, limite do nome e códigos de
  erro das rotas novas — gate no plano 08-06. Este plano assume o contrato recomendado (`{id, client, name}`,
  nome de 1 a 120 caracteres) e isola isso atrás da interface.
- Suposições explícitas do planejador (lacunas ⚠ do UI-SPEC, todas reversíveis):
  - E4 long-text: `maxLength={120}` no nome até a decisão B1.
  - E5 loading: CTA do ID manual vira `Vinculando…` (ao vivo) / `Enviando…` (encerrada), desabilitado,
    `aria-busy`.
  - E5 partial: o ID manual é validado como UUID (`isValidAgenteSessionId`) antes de habilitar o envio.
  - E5 error: cópia `O ID precisa ser um UUID, como aparece no web app do Agente.` (formato inválido); a
    recusa do servidor aparece depois, no status de envio (planos 08-04/08-14), sem perder o valor digitado.
- Claude's Discretion: `id` do `ClientSummary` = id do projeto; dica da linha = nome do projeto.
