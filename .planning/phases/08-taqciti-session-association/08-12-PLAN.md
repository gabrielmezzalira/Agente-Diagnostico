## Plano em 7 seções (obrigatório — CLAUDE.md §"Regras de Planejamento de Tasks")

**1. O que muda (em linguagem comum)**
Até aqui a Taqciti tinha a tela de clientes e os comandos, mas falava com uma "cozinha de mentira" (ou caía no
plano B). Agora ligamos a cozinha de verdade: o backend ganha a porta "criar cliente só com o nome" (já
aprovada pelo time nas decisões B1 e B2) e a Taqciti aprende a pedir ao Agente, pela internet e com a senha
opcional, a lista de clientes, um cliente novo e uma sessão nova. Se o Agente responder algo estranho ou estiver
fora do ar, a Taqciti trata como "lista indisponível" e mostra o plano B.

**2. Como vai ser alterado**
Três commits:
- Task 1 (backend): `ExtensionClientCreate` em `models/extension.py`; `ExtensionRepository` ganha
  `list_client_names` e `insert_project`; `ExtensionSessionService` ganha `create_client`; o router ganha POST
  `/clients`; testes estendidos.
- Task 2 (Taqciti): novos `shared/config/agenteRoutes.ts`, `background/httpClientDirectory.ts`,
  `background/httpSessionGateway.ts` e o teste `httpAgentePorts.test.ts` (fetch simulado).
- Task 3 (Taqciti, comportamento): `background/agenteAssociation.ts` troca as portas "indisponível" pelas HTTP;
  teste ponta a ponta `agenteAssociationHttp.test.ts` + roteiro manual com o backend local.

**3. Riscos de cada ação**
- Task 1 — criar cliente com `mode='sales'` por omissão (prompt de vendas num milestone de discovery).
- Task 1 — aceitar nome vazio/gigante; duplicar cliente por diferença de acento/caixa.
- Task 1 — gravar chave Gemini ou chamar o Vault/CITi Flow nessa rota.
- Task 2 — mandar a chave `x-agente-key` para uma URL `http://` fora de loopback.
- Task 2 — confiar no formato da resposta e exibir lixo/HTML vindo do servidor.
- Task 2 — fetch sem timeout segurar o service worker.
- Task 2 — título de reunião com mais de 200 caracteres (o Meet aceita até 300) virar 422 em `POST
  /webhook/extension/sessions` e a pessoa não conseguir vincular.
- Task 3 — trocar as portas e quebrar os testes do 08-10 (que usam fakes).
- Task 3 — com o backend antigo em produção (sem as rotas), o seletor ficar "carregando" para sempre.

**4. Como prevenir**
- `mode` e `source` fixados no service com os valores registrados no 08-07-SUMMARY (recomendado: `discovery`,
  `extension`); teste confere a linha inserida.
- `ExtensionClientCreate.name: str = Field(min_length=1, max_length=120)` com validator de `strip`; duplicidade
  por `unicodedata.normalize('NFKD')` sem marcas + `casefold()` contra os nomes existentes; testes.
- A linha inserida tem só `name`, `client`, `mode`, `source`; grep negativo de `vault`/`citiflow` no service.
- `buildAgenteJsonRequest` usa `isValidAgenteBackendUrl` (exportada no 08-01) e devolve `null` para URL inválida
  — nada é enviado; header só quando a chave existe.
- Validação zod das respostas (`{id, client, name}[]`, `{id: uuid}`); qualquer desvio → erro
  "indisponível"/"falhou".
- `AbortSignal.timeout(AGENTE_REQUEST_TIMEOUT_MS)` em todo fetch.
- `createSession` corta o nome em `AGENTE_SESSION_NAME_MAX = 200` (mesmo valor de `ExtensionSessionCreate.name`,
  08-07) e omite `name` quando ele fica vazio depois do `trim` (o backend usa "Reunião pela Taqciti"); teste com
  título de 300 caracteres.
- Os testes do 08-10 injetam fakes por `configureAgenteAssociation`, então a troca do padrão não os afeta; o gate
  roda os dois arquivos.
- 404/5xx/erro de rede na lista → `ClientDirectoryUnavailableError` → `{ ok: false, error: 'unavailable' }` →
  plano B; teste com 404.
