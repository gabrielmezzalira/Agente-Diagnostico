## Plano em 7 seções (obrigatório — CLAUDE.md §"Regras de Planejamento de Tasks")

**1. O que muda (em linguagem comum)**
Depois que a reunião acaba, a Taqciti passa a "desligar a luz" da sessão que ela mesma criou no Agente — mas com
calma: espera 10 minutos (a pessoa pode ter caído e voltar para a mesma sala), confere se ainda há falas
esperando para sair e, só então, avisa o Agente para encerrar. Para lembrar de fazer isso mesmo com o motor da
extensão dormindo, usamos o "despertador" do Chrome (`alarms`), uma permissão que não mostra aviso para quem
instala. Sessões que a pessoa colou pelo plano B (criadas no web app) nunca são encerradas pela Taqciti.

**2. Como vai ser alterado**
Dois commits:
- Task 1: `association.ts` ganha o evento `session-finished` e o campo `sessionFinished`; o store inclui o campo
  na lista branca; novo `agenteSessionFinisher.ts` (fábrica + composição de produção) com teste;
  `httpSessionGateway.ts` ganha `createHttpSessionFinisher`.
- Task 2 (fiação + manifesto): `manifest.config.ts` (+ `'alarms'`), `index.ts` (listener síncrono e boot),
  `agenteAssociationLifecycle.ts` (agendar no fim / cancelar ao voltar) e `agenteBindFlow.ts` (agendar depois do
  envio em partes concluído) — 1 a 3 linhas cada.

**3. Riscos de cada ação**
- Task 1 — encerrar antes de a fila esvaziar (as últimas falas chegam numa sessão já encerrada e o pipeline não as
  processa).
- Task 1 — encerrar sessão do plano B (de outra pessoa, criada no web app).
- Task 1 — repetir o encerramento a cada boot (chamadas inúteis).
- Task 2 — registrar o listener de alarme dentro de uma promessa (o MV3 perde o evento ao acordar).
- Task 2 — a permissão nova gerar aviso de atualização para quem já usa a extensão.
- Task 2 — agendar para reuniões sem vínculo.

**4. Como prevenir**
- `countOutboxItemsForSession(sessionId) > 0` → adia 5 min; teste.
- Só origem `picker` com `sessionId`; teste com `manual-id`.
- `session-finished` grava `sessionFinished: true`; o agendamento ignora associações marcadas; teste.
- `chrome.alarms.onAlarm.addListener` no topo do `index.ts` (fora do `ready`), e o handler espera `ready` por
  dentro; grep no `<verify>`.
- `alarms` não está na lista de permissões com aviso do Chrome (documentado no comentário do manifesto); conferir
  no teste manual de atualização (D-20).
- O agendamento só acontece para associação `linked`/`sent`; teste.

**5. Como consertar (plano de rollback)**
- Task 2: `git revert <sha-task-2>` desliga os gatilhos e tira a permissão (sessões voltam a depender do web app
  para encerrar).
- Task 1: `git revert <sha-task-1>` remove o módulo; o campo `sessionFinished` gravado em associações antigas é
  ignorado pela lista branca anterior (inofensivo).
- Alarmes já criados no Chrome de quem testou expiram sozinhos ou somem ao remover a extensão.

**6. Decisões que são do usuário/time**
- Implementa a decisão **B4-b = sw-com-alarms**, tomada no checkpoint do plano 08-15 (pré-condição abaixo). Com
  outra resposta, este plano não executa.
- Claude's Discretion (registrado): adiamento de 5 min quando há fila/erro; reagendamento no boot com a janela
  inteira (10 min), por não se saber quando a reunião acabou.

**7. Verificação (ponta a ponta)**
- `cd taqciti && npx vitest run src/background/agenteSessionFinisher.test.ts` — teste semente: agenda para picker,
  não para manual-id; fila cheia adia; encerra e marca; cancela ao voltar à sala; reagenda no boot.
- `cd taqciti && npm test && npm run typecheck && npm run lint && npm run build`.
- Manual (D-20): terminar uma reunião vinculada pelo seletor e conferir no web app, ~10 min depois, a sessão como
  encerrada.
