## Plano em 7 seções (obrigatório — CLAUDE.md §"Regras de Planejamento de Tasks")

**1. O que muda (em linguagem comum)**
Criamos as "peças de Lego" do aviso: uma bolinha amarela com um "!" que dá um pulinho a cada 5 segundos
(como um app que avisa que tem notificação, mas sem som e sem tirar a pessoa da reunião) e o cartão que
pergunta "Esta reunião é de qual cliente?" com os botões "Selecionar cliente agora" e "Depois". Também
ensinamos a janela de confirmação já existente a mostrar outro texto no botão de recusar (por exemplo
"Manter reunião" em vez de "Cancelar"). Nada disso aparece na tela ainda: as peças só são encaixadas no
painel do Meet no plano 08-14.

**2. Como vai ser alterado**
Dois commits:
- Task 1 (kit): `taqciti/src/shared/ui/Icon.tsx` ganha `'alert'` em `IconName` e em `PATHS` (mecânico);
  `taqciti/tailwind.config.ts` ganha o keyframe `nudge` e a animação `nudge` (mecânico);
  `taqciti/src/shared/ui/ConfirmModal.tsx` ganha a prop `cancelLabel?: string` (padrão `'Cancelar'`) — muda
  a API de forma retrocompatível; novo `ConfirmModal.test.tsx`.
- Task 2 (componentes): novos `AgenteNudge.tsx` e `AgenteDecisionCard.tsx` em
  `taqciti/src/sidepanel/components/`, cada um com teste. Componentes puros, sem chamada de API, sem hook de
  dados.

**3. Riscos de cada ação**
- Task 1 — keyframe com opacidade deixar a bolha invisível quando o quadro de animação não roda (lição do
  `dock-in`).
- Task 1 — mudar o texto padrão do `ConfirmModal` e alterar telas atuais ("Apagar do histórico?").
- Task 1 — ícone novo com espessura/estilo diferente do kit.
- Task 2 — o `Esc` dentro do cartão também minimizar o painel (o painel ouve `Esc` em `document`).
- Task 2 — o aviso roubar foco ao aparecer (`autoFocus`) e atrapalhar quem está digitando no chat do Meet.
- Task 2 — cor accent (verde) na bolha, contrariando o UI-SPEC (é warning).

**4. Como prevenir**
- Keyframe só com `transform: translateY` (0 → -4px → 0 → -2px → 0 nos primeiros ~20% e repouso no resto);
  grep negativo de `opacity` dentro do bloco `nudge`.
- `cancelLabel` com padrão `'Cancelar'`; teste "sem cancelLabel mostra Cancelar" + "com cancelLabel mostra o
  texto"; nenhum chamador existente é alterado neste plano.
- `PATHS.alert` com `strokeWidth` do mesmo padrão dos vizinhos (1.8) e `currentColor`.
- `AgenteDecisionCard` trata `onKeyDown` no próprio cartão: `Escape` → `event.stopPropagation()` +
  `event.nativeEvent.stopImmediatePropagation()` + `onDefer()`; teste prova que um listener de `keydown` em
  `document` não recebe o evento.
- Nenhum `autoFocus` nos dois componentes; teste confere que `document.activeElement` não muda ao montar.
- Classes literais warning do UI-SPEC (`bg-[#F2C94C]`, texto `text-background`); teste confere a ausência de
  `bg-primary` na bolha.

**5. Como consertar (plano de rollback)**
- Task 1: `git revert <sha-task-1>` — o ícone e o keyframe somem (nenhum consumidor ainda) e o
  `ConfirmModal` volta a fixar "Cancelar" (o comportamento atual).
- Task 2: `git revert <sha-task-2>` — remove os dois componentes; nada os importa até o plano 08-14.
- Sem backend, banco ou produção envolvidos.

**6. Decisões que são do usuário/time**
- Nenhuma DECISÃO EM ABERTO neste plano. Executa D-06, D-07 e o contrato aprovado `08-UI-SPEC.md`
  (decisões a, b, d confirmadas no contrato).
- Claude's Discretion (registrado): componentes em `taqciti/src/sidepanel/components/` (mesma pasta de
  `AgenteApiKeyField.tsx`, usados pelas duas superfícies); a prop `bouncing` do `AgenteNudge` é decidida por
  quem compõe (plano 08-14), o componente não conhece o estado da associação (props mínimas, ISP).

**7. Verificação (ponta a ponta)**
- `cd taqciti && npx vitest run src/shared/ui/ConfirmModal.test.tsx` — teste semente do acréscimo ao kit.
- `cd taqciti && npx vitest run src/sidepanel/components/AgenteNudge.test.tsx src/sidepanel/components/AgenteDecisionCard.test.tsx`.
- `cd taqciti && npm test && npm run typecheck && npm run lint`.
- Visual (no fim da fase, com a fiação do 08-14): bolha e cartão conferidos no teste manual D-20.
