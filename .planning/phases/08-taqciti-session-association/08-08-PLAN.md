## Plano em 7 seções (obrigatório — CLAUDE.md §"Regras de Planejamento de Tasks")

**1. O que muda (em linguagem comum)**
Hoje, para cadastrar um cliente no Agente, é obrigatório colar uma chave de IA (Gemini) daquele projeto. Isso
impede criar um cliente rápido pela Taqciti, só com o nome. A proposta (D-15) é: a chave por projeto vira
opcional, e quando ela não existe o Agente usa a chave do próprio servidor — o que ele já faz por baixo dos
panos. Como isso muda o contrato da API e o formulário do web app, quem decide é o time (B2). Também pedimos ao
time para confirmar que a chave do servidor está configurada em produção; sem ela, um projeto sem chave
própria ficaria "mudo" (sem IA).

**2. Como vai ser alterado**
- Task 1: `checkpoint:decision` B2 (+ confirmação A6).
- Task 2 (commit backend): `backend/app/models/projects.py` (`gemini_api_key: Optional[str] = None`),
  `backend/app/routers/projects.py` (`create_project` só chama `_vault_store` quando há chave — mesmo padrão já
  usado para `pricing_api_key`), `backend/tests/test_projects.py` (testes novos; os existentes não mudam).
- Task 3 (commit frontend): `frontend/src/pages/ProjectFormPage.tsx` (campo sem `required`, texto de apoio) e
  `frontend/src/pages/ProjectDetailPage.tsx` (cópia neutra quando não há chave).

**3. Riscos de cada ação**
- Task 1 — decidir pelo time (contrato de API, CLAUDE.md).
- Task 2 — projeto criado sem chave e sem `GEMINI_API_KEY` no servidor: pipeline sobe e nunca gera IA.
- Task 2 — quebrar a edição de projeto (o `ProjectUpdate` já é opcional) ou o Precificador.
- Task 2 — gravar `gemini_api_key_secret_id: None` explicitamente e sobrescrever algo.
- Task 3 — o formulário ainda mandar `gemini_api_key: ''` e o backend tentar guardar string vazia no Vault.
- Task 3 — quebrar o build do frontend (TypeScript).

**4. Como prevenir**
- Task 1 é `gate="blocking-human"`; a confirmação A6 é parte da resposta.
- Teste "sem chave → Vault não chamado e a linha inserida não tem `gemini_api_key_secret_id`"; condicional
  `if payload.gemini_api_key:` (string vazia também conta como ausente).
- Não tocar `update_project` nem `pricing_api_key`; os testes existentes de `test_projects.py` continuam verdes.
- No formulário, remover a chave vazia do payload na criação (como já é feito na edição).
- `npm --prefix frontend run build` e `npm --prefix frontend test` no `<verify>`.

**5. Como consertar (plano de rollback)**
- Task 2: `git revert <sha-task-2>` devolve a chave obrigatória; projetos já criados sem chave continuam
  funcionando pelo fallback do servidor (nenhum dado precisa ser alterado).
- Task 3: `git revert <sha-task-3>` devolve o campo obrigatório no formulário.
- Em produção, rollback = novo deploy sem os commits. Nenhuma migração.

**6. Decisões que são do usuário/time**
- **DECISÃO EM ABERTO B2 — PARAR na Task 1 até o time decidir** (contrato `ProjectCreate` + formulário F1).
- **Confirmação A6 (fora do repo):** `GEMINI_API_KEY` configurada no Railway de produção — só o time consegue
  verificar; nunca ler `.env` para isso.
- Se o time **rejeitar**: este plano para, o plano 08-12 (criar cliente pela Taqciti) não executa, e o
  formulário de criar cliente do UI-SPEC precisa voltar ao `/gsd-ui-phase` para ganhar o campo de chave.

**7. Verificação (ponta a ponta)**
- `cd backend && python -m pytest tests/test_projects.py -x -q` (teste semente: criar sem chave não chama o
  Vault; com chave chama).
- `npm --prefix frontend run build` e `npm --prefix frontend test`.
- Manual (fim da fase): criar um projeto sem chave no web app local e abrir uma sessão — o pipeline responde
  usando a chave do servidor.
