<objective>
Fechar o gap G-06-1: no popup da extensão Chrome, o campo "Chave de autenticação (opcional)"
(`input#extension-key`) apaga o texto digitado pelo usuário antes que ele consiga clicar em Salvar.

A causa raiz confirmada (ver sessão de debug) é que `render()` em `extension/popup.js` reescreve
`extensionKeyInput.value` de forma incondicional a cada tick do `setInterval` de 3s (polling de
`GET_STATE`), sem checar se o campo está em foco. Como `state.extensionKey` só é atualizado quando o
usuário clica em Salvar, qualquer digitação ainda não salva é sobrescrita pelo valor antigo
(tipicamente vazio) no próximo tick. O mesmo defeito estrutural atinge `backendUrlInput`.

Propósito: tornar a configuração da chave (feature de opt-in webhook auth, TAQ-03) usável de verdade —
hoje ela funciona byte-a-byte no header, mas a UX de digitar a chave é falha e pode levar o usuário a
salvar um valor errado/vazio sem perceber.

Output: um helper puro e testável que só escreve o valor de um input quando ele não está em foco,
aplicado aos dois campos de configuração afetados, com teste unitário como semente.
</objective>

## Plano da Task — 7 seções obrigatórias (CLAUDE.md)

> Este bloco atende à regra de planejamento de tasks do projeto: qualquer pessoa do time, técnica ou
> não, deve entender o que muda, os perigos e como voltar atrás antes de qualquer linha ser alterada.

**1. O que muda (em linguagem comum)**
Hoje, quando você abre o popup da extensão e começa a digitar a chave de autenticação, o campo se
apaga sozinho a cada 3 segundos — antes de você conseguir clicar em Salvar. Isso acontece porque a
extensão "recarrega" os campos a cada 3s com o último valor salvo (que ainda está vazio enquanto você
digita). É como um formulário que insiste em se auto-preencher com o valor antigo enquanto você tenta
escrever o novo. A mudança faz a extensão parar de sobrescrever um campo **enquanto você está com o
cursor nele (digitando)**. Vale para o campo da chave e para o campo de URL do backend (que tinha o
mesmo defeito, só não foi notado por já vir pré-preenchido). Por quê: sem isso, o usuário pode salvar
uma chave incompleta/errada sem perceber e a autenticação do webhook falha silenciosamente.

**2. Como vai ser alterado**
Dois commits atômicos:
- **Commit 1 (Task 1):** criar `extension/popup-utils.js` com uma função pura
  `applyInputValueUnlessFocused` e seu teste `extension/popup-utils.test.js` (usando o runner embutido
  `node:test`, sem instalar nada). É a peça central da correção, isolada e testada.
- **Commit 2 (Task 2):** em `extension/popup.js`, dentro de `render()`, trocar as duas atribuições
  diretas de `.value` pelo helper; em `extension/popup.html`, adicionar `<script src="popup-utils.js">`
  imediatamente antes de `<script src="popup.js">`.
Mecânico: adicionar a tag `<script>`. Muda comportamento: a proteção de foco dentro de `render()`.

**3. Riscos de cada ação**
- Criar `popup-utils.js`: se o arquivo usar `export` de ES module, o popup quebra com SyntaxError
  (popup.js é script clássico).
- Adicionar a tag `<script>` na ordem errada: `popup.js` rodaria antes do helper existir → ReferenceError,
  popup morre.
- Alterar `render()`: pode quebrar o preenchimento inicial dos campos (campo nunca preenche) ou regredir
  o envio do header x-agente-key.
- Teste `node:test`: ambiente com node muito antigo (< 18) não tem o runner `--test`.

**4. Como prevenir**
- Usar padrão CJS-guard (`typeof module !== 'undefined'`) em vez de `export` ES — funciona no browser e
  no node sem conversão de módulo.
- Colocar `<script src="popup-utils.js">` exatamente antes de `<script src="popup.js">`.
- Cobrir com o teste os três casos (escreve quando não focado, NÃO sobrescreve quando focado, escreve
  string vazia quando não focado) e revalidar o header manualmente (Teste 2 do UAT já passa — re-testar).
- Rodar `node --test` localmente; node 18+ é suficiente.

**5. Como consertar (plano de rollback)**
- `git revert` do commit 2 restaura `render()` e `popup.html` ao estado atual (o bug volta, mas o popup
  volta a funcionar).
- `git revert` do commit 1 remove o helper e o teste.
- Nenhum dado persistido é afetado — `chrome.storage.local` (sessionId, backendUrl, extensionKey,
  questions) permanece intacto.

**6. Decisões que são do usuário/time (DECISÃO EM ABERTO)**
- Nenhuma decisão irreversível nesta correção. **Não** vamos converter `popup.js` para ES module (isso
  seria refator de risco, à parte); mantemos script clássico. Padronizar a extensão em ES modules no
  futuro é decisão do time.
- A ativação real de `EXTENSION_SHARED_KEY` em produção (Railway) permanece **DECISÃO EM ABERTO** (D-03
  da Fase 06) — fora do escopo desta correção; nenhuma task aqui toca ambiente real.

**7. Verificação (ponta a ponta)**
- Automático: `node --test extension/popup-utils.test.js` (comportamento do helper) + greps de fiação.
- Manual (real, reproduz o Teste 1 do UAT): carregar a extensão descompactada no Chrome, abrir o popup,
  clicar no campo "Chave de autenticação", digitar devagar (mais de 3s) sem salvar → o texto permanece;
  clicar em Salvar → persiste; disparar um chunk real → `POST /webhook/extension` carrega o header
  `x-agente-key` com o valor salvo. Repetir digitando no campo "URL do backend".

    - Test 3 (não focado, valor vazio): value === '' e activeElement diferente → escreve '' (permite
      limpar uma chave salva); inputEl.value === ''.
    - Test 4 (nada focado): activeElement === null → escreve o valor.
    Os testes usam objetos simples ({ value: ... }) como fake de input — sem DOM real, sem jsdom.
  </behavior>
  <action>
    Criar `extension/popup-utils.js` como script clássico (NÃO usar `export`/`import` de ES module —
    quebraria o popup, que carrega scripts clássicos). Declarar no topo, com `function`, a função pura
    `applyInputValueUnlessFocused(inputEl, value, activeElement)` cujo único trabalho é: se
    `inputEl === activeElement` (o campo está em foco), não faz nada e retorna false; caso contrário,
    atribui `inputEl.value = value` e retorna true. Sem side effects além dessa atribuição, sem acessar
    `document` ou `chrome` globalmente (o activeElement chega por parâmetro) — Single Responsibility e
    testável isoladamente conforme CLAUDE.md.

    Ao final do arquivo, exportar em modo CommonJS SOMENTE sob guarda de ambiente:
    `if (typeof module !== 'undefined' && module.exports) { module.exports = { applyInputValueUnlessFocused } }`.
    No browser `module` é indefinido, então a linha é ignorada (sem ReferenceError, pois usa `typeof`) e
    a função fica disponível como global para `popup.js`. No node ela é exportada para o teste.

    Criar `extension/popup-utils.test.js` usando o runner embutido do node (`const { test } = require('node:test')`,
    `const assert = require('node:assert')`) — sem instalar nenhuma dependência. Importar via
    `require('./popup-utils.js')` e cobrir os 4 casos do bloco behavior. Este é o teste-semente exigido
    pelo CLAUDE.md.
