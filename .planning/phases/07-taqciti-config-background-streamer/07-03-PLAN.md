## Plano em 7 seções (obrigatório — CLAUDE.md §"Regras de Planejamento de Tasks")

**1. O que muda (em linguagem comum)**
Depois do plano 02, a "gaveta de configurações" do Agente existe, mas só dá para mexer nela pelo console
de desenvolvedor. Este plano coloca um painel de controle de verdade na tela larga da Taqciti (a mesma que
abre no painel lateral do Chrome ou pelo botão "Abrir numa aba"): um interruptor para ligar o envio ao
vivo, um campo para colar o ID da sessão do Agente, a URL do backend e, se o time ativar a proteção da
Fase 6, a chave — que aparece sempre com bolinhas, como senha. Uma linha de status diz em português
simples se está enviando ou o que falta. A tela inicial ganha um link para esse painel. Nada disso muda o
painel flutuante que aparece dentro do Meet nem o clique no ícone da extensão.

**2. Como vai ser alterado**
Dois commits atômicos, nesta ordem:
- **Task 1 (TDD na rota + tela):** `taqciti/src/sidepanel/route.ts` ganha o campo `agenteConfig` em
  `WideViewRequest` e a constante `AGENTE_CONFIG_SEARCH = '?view=agente'`; `route.test.ts` atualiza as 5
  expectativas existentes (mecânico: acrescentar `agenteConfig: false`) e ganha casos novos;
  `App.tsx` renderiza `<AgenteConfigScreen />` quando o pedido existir (1 `if` antes do de `history`); novo
  hook `taqciti/src/shared/hooks/useAgenteConfigForm.ts` (toda a lógica de estado) e nova tela
  `taqciti/src/sidepanel/screens/AgenteConfigScreen.tsx` (só layout). Muda comportamento só para quem
  abre `?view=agente`.
- **Task 2 (entrada + teste de componente + docs):** `HomeScreen.tsx` ganha um link
  `<a href={AGENTE_CONFIG_SEARCH}>`; novo `AgenteConfigScreen.test.tsx`; `taqciti/docs/publicar-release.md`
  ganha uma subseção sobre as variáveis `VITE_AGENTE_*`. Depois, a verificação final da fase inteira.

**3. Riscos de cada ação**
- Task 1 — mudar o formato de `WideViewRequest` quebra os 5 testes existentes de `route.test.ts` que
  comparam o objeto inteiro com `toEqual`.
- Task 1 — colocar o `if` do Agente depois do `switch` de fase: durante uma gravação a tela nunca
  apareceria (o mesmo defeito que `route.ts` documenta para o histórico).
- Task 1 — assinatura da config sobrescrevendo o que a pessoa está digitando (o bug G-06-1 da Fase 6, lá
  com polling; aqui com `onChanged` vindo de outra aba ou da Fase 8).
- Task 1 — lógica de negócio (prontidão, normalização) dentro do JSX, contra a regra do CLAUDE.md.
- Task 1 — digitar no campo disparar atalhos da página (o "m" do Meet muta o microfone) se o input não
  segurar a propagação do teclado.
- Task 2 — o link virar navegação para fora da extensão ou perder o caminho de volta.
- Task 2 — teste de componente sem testing-library (não é dependência do projeto) ficar frágil.
- Task 2 — documentar as variáveis `VITE_AGENTE_*` na tabela "não têm conserto" do `publicar-release.md`,
  sugerindo errado que elas são fixas no bundle (na verdade são padrões editáveis em runtime).
- Verificação final — `npm run build` gerar `taqciti/dist/` rastreado pelo git.

**4. Como prevenir**
- Atualizar as 5 expectativas existentes no mesmo commit e rodar `route.test.ts` antes de seguir.
- `if (request.agenteConfig)` como PRIMEIRA decisão do `App` + caso de teste de rota; verificação manual
  com uma reunião gravando.

  campos não editados; salvar limpa as marcas e relê o valor normalizado. Teste de componente específico.
- Prontidão via `getStreamingReadiness` (plano 01) chamada no hook; a tela só mapeia o resultado para um
  texto (constante `READINESS_LABELS`).
- Usar `TextField` de `@/shared/ui/Field` (já para a propagação do teclado) para os três campos de texto.
- Link relativo `?view=agente` (fica na mesma página da extensão) e link "Voltar" relativo `?`, já coberto
  por `readWideViewRequest('?')` no teste existente.
- Teste no padrão de `TranscriptView.test.tsx` (`createRoot` + `act`, `IS_REACT_ACT_ENVIRONMENT`), com o
  setter nativo de `value` + evento `input` para simular digitação.
- Subseção própria "Integração com o Agente Diagnóstico (opcional)", fora da tabela "não têm conserto".
- `git status --porcelain -- taqciti` vazio depois do build (o `.gitignore` da Taqciti já cobre `dist/`).

**5. Como consertar (plano de rollback)**

**6. Decisões que são do usuário/time**

  D-03 de lá) — esta tela só permite colar a chave quando o time decidir.
- **Fora do escopo, registrado para o time (não bloqueia):** a descrição do manifesto ("sem integração com
  nenhum backend") e o comentário de cabeçalho de `background/index.ts` ficam desatualizados com o
  streaming opcional; mudar o texto do manifesto altera o que aparece na tela de instalação/Web Store, então
  não é mexido aqui.
- **Resolvido sob Claude's Discretion (reversível, sem parar):** a tela mora na saída larga
  (`src/sidepanel`), aberta por `?view=agente`, com link na HomeScreen — e não no painel injetado
  (`PanelApp.tsx`, 1349 linhas, arriscado para esta fase) nem via `default_popup` (quebraria o clique no
  ícone documentado em `manifest.config.ts:76-85`). Caminho durante uma chamada: painel flutuante →
  "Ver o histórico" → "Abrir numa aba" → link "Agente Diagnóstico". Rótulos dos campos em português
  seguindo o padrão das telas existentes.
