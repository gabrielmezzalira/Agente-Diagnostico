## Plano em 7 seções (obrigatório — CLAUDE.md §"Regras de Planejamento de Tasks")

**1. O que muda (em linguagem comum)**
Hoje a Taqciti (a extensão que captura as legendas do Google Meet) vive num repositório separado e só
guarda a transcrição no computador de quem usa — ela não conversa com o Agente Diagnóstico durante a
chamada. Este plano faz duas coisas. Primeiro, "muda a Taqciti de casa": copia o repositório inteiro dela,
com toda a história de commits, para dentro de uma pasta `taqciti/` deste repositório — como trazer uma
caixa de mudança fechada e só etiquetá-la, sem abrir nem misturar com nada da casa. Segundo, liga um
"cano" novo: enquanto a reunião acontece, a cada pequeno lote de legendas (o mesmo lote que a Taqciti já
usa para salvar o estado a cada 250 ms), ela manda para o backend do Agente só as palavras novas daquela
fala — nunca a fala inteira de novo, para não duplicar linhas no banco. Esse cano vem **fechado** de
fábrica: ninguém manda nada até alguém decidir ligar e informar para qual sessão do Agente enviar. Se a
internet falhar, a captura continua igual; o envio perdido só vira um aviso no log.

**2. Como vai ser alterado**
Três commits atômicos, nesta ordem:
- **Task 1 (importação — Git, não código):** `git fetch` do `main` da Taqciti, conferência do SHA exato
  pesquisado (`c41309a…`), e `git subtree add --prefix=taqciti FETCH_HEAD` **sem** `--squash`. Gera um
  merge commit que só adiciona arquivos sob `taqciti/`. Mecânico; nenhum comportamento do Agente muda.
  Se o GSD tiver deixado `.planning/STATE.md`/`ROADMAP.md` modificados, eles vão num commit
  `docs(07)` separado ANTES do subtree (o subtree exige árvore limpa).
- **Task 2 (TRACER — muda comportamento, mas desligado por padrão):** `npm ci` em `taqciti/`; cria
  `taqciti/src/shared/config/agenteConfig.ts` (padrões da build + normalização + prontidão + montagem da
  requisição), `taqciti/src/features/agente/wordDelta.ts` (função pura do delta), 
  `taqciti/src/background/agenteStreamer.ts` (fila + cursor + envio) e o teste ponta a ponta
  `agenteStreamer.test.ts`; em `sessionController.ts` só entra 1 import + 1 linha em `flushState()`.
- **Task 3 (expansão — testes de borda da parte pura):** `wordDelta.test.ts` e `agenteConfig.test.ts`
  (vazio, codificação, idempotência, captionId reaproveitado, reunião nova, normalização, contrato). Só

**3. Riscos de cada ação**
- Task 1 — working tree sujo: `git subtree add` recusa rodar, ou (se forçado) mistura mudanças do usuário
  no commit da importação, quebrando D-02.
- Task 1 — upstream andou: se o `main` da Taqciti ganhou commits depois da pesquisa, os planos (que citam
  linhas e assinaturas de `c41309a`) podem não bater com o código importado.
- Task 1 — `--squash` por engano: perde os 105 commits de histórico (contraria D-01).
- Task 1 — segredo no histórico importado: se algum commit antigo da Taqciti tiver uma chave, ela passa a
  viver também no histórico deste repositório (e vai junto no push).
- Task 1 — CI da Taqciti fica inerte: o GitHub só lê `.github/workflows` da raiz; `taqciti/.github/` deixa
  de rodar typecheck/lint/test/build automaticamente.
- Task 2 — `npm ci` dentro do OneDrive pode falhar com EPERM/EBUSY (sincronização travando arquivos) ou
  sujar o `git status` se `node_modules/` não estiver ignorado.
- Task 2 — plugar o streamer de forma bloqueante (`await` do fetch) em `flushState()` atrasaria a gravação
  do estado e o broadcast para o painel — a captura engasgaria com a rede lenta.
- Task 2 — chavear o cursor só por `captionId` (como no esboço do RESEARCH) cortaria o começo de um
  segmento novo que reaproveita o mesmo `captionId` (troca de falante / linha reaproveitada).
- Task 2 — dois flushes concorrentes (um do timer, um de evento não agrupável) enviariam o mesmo delta duas
  vezes se o cálculo não for serializado.
- Task 2 — vazar texto/session_id/chave no console do service worker.
- Task 3 — um teste de borda revelar bug no código do tracer e a correção mudar o comportamento do caminho
  feliz.

**4. Como prevenir**
- Precondição somente-leitura da Task 1 (`git status --porcelain` sem nada do usuário) — para antes de
  qualquer escrita; o executor nunca faz stash/commit/descarte das mudanças do usuário.
- `git rev-parse FETCH_HEAD` tem que ser exatamente `c41309a1c58f3fa06095db877e6dc8f1dbd65635`; diferente →
  para sem importar (DECISÃO EM ABERTO, seção 6).
- Comando literal sem `--squash`; verificação automática de `git rev-list --count HEAD^2` = 105 e de que o
  diff do merge contra o primeiro pai só tem caminhos `taqciti/`.
- Varredura do histórico importado por NOMES de arquivo de segredo e por padrões de chave (só contagem,
  nunca imprimindo valor) — qualquer ocorrência → para (pesquisa prévia no clone já deu zero).
- CI inerte: a verificação local da fase roda os mesmos 4 passos do CI da Taqciti (typecheck, lint, test,
  build) — no plano 03.
- `npm ci` (lockfile exato, sem pacote novo); em EPERM/EBUSY tentar 1 vez de novo; persistindo, parar e
  pedir ao usuário que pause a sincronização do OneDrive. Conferir `git check-ignore` de
  `taqciti/node_modules`.
- Streamer chamado com `void … .catch(logger.error)` depois de `broadcast()`; `send` com
  `AbortSignal.timeout(10_000)`; teste com fetch rejeitando prova que `dispatch` resolve e o estado é gravado.
- Chave do cursor `${índice}:${captionId}` + teste específico (Task 3) para captionId reaproveitado.
- Fila de promessas no streamer (padrão da fila de `prefsStore.ts`) + teste de chamadas concorrentes.
- Só `logger` (`@/shared/services/log`, que já filtra por allowlist) e grep negativo no fim da Task 2.
- Task 3: se precisar corrigir código, rodar de novo o teste ponta a ponta da Task 2 antes do commit.

**5. Como consertar (plano de rollback)**
- **Task 1 (merge commit do subtree):** enquanto a branch NÃO foi enviada ao remoto e não há commits por
  cima: `git reset --keep HEAD^1` (desfaz só o merge; `--keep` recusa se houver mudança local que se
  perderia). Se já houver commits por cima ou a branch já foi enviada: `git revert -m 1 <sha-do-merge>` —
  um `git revert` simples FALHA em merge commit ("commit is a merge but no -m option was given"); o `-m 1`
  mantém a linha local como principal e remove a pasta `taqciti/`. Nada fora de `taqciti/` é afetado. O
  commit `docs(07)` de bookkeeping (se existir) não precisa ser revertido.
- **Task 2:** `git revert <sha-da-task-2>` remove os 3 arquivos novos, o teste e a linha do
  `sessionController.ts` — a Taqciti volta a ser só local. `node_modules/` é ignorado; se quiser, apagar
  `taqciti/node_modules` à mão.
- **Task 3:** `git revert <sha-da-task-3>` remove os testes (e a correção, se houver) sem afetar a Task 2.
- Nenhuma ação toca o backend, o banco ou a produção — não há o que restaurar fora do Git.
