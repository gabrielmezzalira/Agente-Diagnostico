## Directory Purposes

### **backend/app/**

**Purpose:** FastAPI application code.

**Key Files:**

- `main.py` — Entry point; creates FastAPI app, mounts static files, includes routers.
- `database.py` — Supabase client factory; used via `Depends(get_supabase)` in routers.
- `config.py` — Load environment variables; contains `Settings` class with defaults.

**Contains:**

- HTTP routers (8 files) — handle requests
- Services (13+ files) — business logic
- Repositories (1 file) — data access layer
- Models (5 files) — Pydantic schemas
- Core (2 files) — factories, helpers

**Organize by:**

- **Feature-based grouping within services** — `llm.py` handles all LLM calls; `pipeline.py` handles session orchestration; `pricing_*_service.py` handle pricing domain.
- **Thin routers** — Validate input, call service, return response. No business logic.
- **Layered access** — Routers → Services → Repositories → Database.

---

### **frontend/src/**

**Purpose:** React application code.

**Entry:** `main.tsx` → renders `<App/>` → Router with 7 pages.

**Organize by:**

- **Pages as routes** — One page per major route (projects, sessions, pricing).
- **Hooks for state** — `useSessionWS` (real-time), `usePricing` (data fetching).
- **Lib for utilities** — `api.ts` (REST client), `useSessionWS.ts` (WebSocket), `pricingCalculator.ts` (pure functions).
- **Components for UI** — Reusable presentational components (currently minimal).

**Patterns:**

- **No API calls in components** — use hooks.
- **No business logic in pages** — compose hooks.
- **Props over context** — local state OK; avoid context unless genuinely global.

---

### **extension/**

**Purpose:** Chrome extension for Google Meet transcript capture.

**Files:**

- `manifest.json` — Permissions, scripts, icons.
- `background.js` — Service worker; routes messages to `POST /webhook/extension`.
- `popup.html` + `popup.js` — UI for session ID input, start/stop buttons.
- `content_meet.js` — Content script on Meet; captures captions, sends via `chrome.runtime.sendMessage`.
- `content_app.js` — Generic fallback (unused in v2).

**Organize by:**

- Minimal code per file (background.js, content_meet.js are already ~100–200 lines).
- Async/await for clarity.
- No heavy dependencies (vanilla JS only).

---

### **diagnostico/ (v1 — LEGACY)**

**Purpose:** Standalone CLI app for offline diagnostic interviews.

**Entry:** `main.py` — Terminal UI via `realtime_agent.py` or `agent.py`.

**Files:**

- `main.py` — CLI argument parsing; selects mode (interactive, realtime, etc.).
- `agent.py` — Interactive mode; prompts user for answers one per line.
- `realtime_agent.py` — Real-time mode; monitors transcript buffer, emits alerts.
- `prompts.py` — Fixed system prompts (constants, not dynamic like v2).
- `config.py` — Environment variables (separate from v2).
- `llm/` — Gemini client.
- `analysis/`, `coverage/`, `transcription/`, `ui/` — Domain modules.

**Status:** Orphaned. Not connected to v2 backend, extension, or frontend. Runnable standalone. Use for offline terminal diagnostics only.

**Rules:**

- Don't import v2 code from `backend/` or `frontend/`.
- Don't break its imports (it uses `from config import ...` as top-level, not from `backend.app.config`).
- If removing, delete entire folder (recoverable via git history).

---

### **supabase/migrations/**

**Purpose:** Database schema version control.

**Files:**

- `001_initial_schema.sql` — Create projects, sessions, questions, red_flags, coverage_snapshots, reports, question_bank, session_prompts, transcript_chunks tables.
- `002_vault_setup.sql` — Enable Supabase Vault extension; create RPC functions for secret storage.
- `003_coverage_snapshots.sql` — Add coverage tracking.
- (more as schema evolves)

**Pattern:**

- One migration per logical change.
- Never modify old migrations; add new ones.
- Idempotent (use `IF NOT EXISTS`, etc.).
- Version controlled; applied in order on deploy.

## Naming Conventions

### Files

| Pattern | Example | Usage |
|---------|---------|-------|
| `{entity}.py` | `projects.py`, `sessions.py` | Routers, services, models |
| `{entity}_service.py` | `llm_service.py`, `pricing_service.py` | Business logic (services) |
| `{entity}_repository.py` | `pricing_repository.py` | Data access |
| `use{Hook}.ts` | `useSessionWS.ts`, `usePricing.ts` | React hooks |
| `{Page}Page.tsx` | `SessionActivePage.tsx`, `HomePage.tsx` | Page components |
| Index files | `__init__.py`, `index.tsx` | Module entry (export all public) |

### Directories

| Pattern | Example | Contents |
|---------|---------|----------|
| Plural nouns | `routers/`, `services/`, `models/` | Collections of modules |
| Feature domain | `backend/app/` | A feature or domain (projects, sessions, pricing) |
| Utilities | `lib/`, `core/` | Shared helpers, factories |
| Type definitions | `models/`, `types/` | Data contracts |

### Functions & Classes

| Pattern | Example | Notes |
|---------|---------|-------|
| `get_*` | `get_supabase`, `get_project` | Fetch from DB or return dependency |
| `async def` | `async def classify_coverage(...)` | Async operations (LLM, DB, I/O) |
| `PascalCase` | `SessionPipeline`, `ProjectCreate` | Classes, types, schemas |
| `snake_case` | `budget_remaining`, `get_transcript_text` | Functions, methods, variables |
| `_private` | `_vault_store`, `_coverage_task` | Internal (not part of public API) |
